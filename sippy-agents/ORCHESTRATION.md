# Sippy — וורקפלואו משולב (Orchestration)

## עקרון
כל סוכן רץ לבד (workflow פנימי ב-md שלו). המערכת מריצה אותם **בשרשרת** כשיש תלות, ו**במקביל** כשאין.

## מחזור בנייה (לכל שינוי במוצר)
```
משימה
  → Build (L2)
     → [ QA ∥ Art Director ∥ UX Auditor ]   (במקביל — אין תלות ביניהם)
        → סינתזה → ורדיקט אלייך (PASS/FAIL)
```

## מחזור השקה
```
build שעבר PASS → Release (הכנה) → אישורך → פריסה חיה → Analytics מתחיל למדוד
```

## מחזור צמיחה (יומי/שבועי, מתוזמן)
```
יומי:   Distribution Scout ∥ (לפי צורך) Content/Copy → /queues → אישורך
שבועי:  Analytics → Product Analyst → הצעות → תעדוף שלך → Build/Experiment
```

## מקביל מול שרשרת — סיכום
- **במקביל:** QA, Art Director, UX Auditor (ביקורות בלתי־תלויות); Scout ו-Analytics.
- **בשרשרת:** Build → ביקורות → ורדיקט; Analytics → Product Analyst; Release → פריסה.
- **תמיד אחרון:** שער אנושי לכל דבר בלתי־הפיך / כסף / פרסום.

## Synthetic User Researcher — שילוב לפי שלב (אוטומטי)
- **Phase 0:** אחרי Product Analyst → תכנון מטריצת 30–50 פרופילים (תכנון בלבד).
- **Phase 1:** במקביל ל-QA, כשהלופ הראשי יציב → Core 10–12; חוסם יציאה מ-Phase 1 אם יש Blocker.
- **Phase 2:** חלק משער "מוכנות להשקה" (עם Analytics) → Expanded 25–30; חוסם גיוס בטא אמיתי אם יש חסם שמשתמש אמיתי ייתקל בו מיד.
- **Phase 3+:** משווה תחזיות סינתטיות מול פידבק בטא אמיתי; פידבק אמיתי הוא הקובע.
- **רגרסיה (T4):** אחרי כל שינוי בזרימת first-use/undo/goal/units/reset/שפה-RTL/PWA/קופי-השקה → תת-קבוצה רלוונטית בלבד.
